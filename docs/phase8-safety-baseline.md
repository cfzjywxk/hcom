## Standalone project repositories

The developer repository is a standalone non-bare repository below Store v1.
It must not be a linked worktree and must not share an object database with the
source repository. The trusted host create gate must:

- fix the source top-level, Git admin/common/object directory, object format,
  target ref, and exact base commit;
- reject bare and linked-worktree sources, submodules, shallow/partial/promisor
  repositories, replace or graft configuration, alternates, and external Git
  admin or object paths;
- use an exact Git executable to create a full reachable-closure pack for the
  base and validate it in a private quarantine with strict index/fsck checks;
- import only that verified pack into the standalone repository, create a
  private branch, and check out the exact clean base;
- prohibit hardlinks, local shared clones, temporary source refs, or worker
  writes to the source object store.

Each reviewer snapshot is another standalone detached repository generated by
the trusted host from the exact developer base and head. It shares no object
database or hardlinks with the developer or source repository. Reviewers never
receive the developer repository path and receive the snapshot read-only.

## Verified append-only final object import

Only an explicit human foreground command may request final project apply.
Architect tools and workers have no final-apply capability.

Every Git command on the create or apply path must use a fixed executable
identity, version, and contract hash. It must disable system/global
configuration and replace objects. Every apply-path command must also set
`core.hooksPath` to a validated current-user-owned, mode-0700, private empty
directory. A missing, non-empty, symlinked, or changed hook directory fails
closed. A red test must prove that a `reference-transaction` sentinel hook
cannot run.

Phase 8 v1 rejects final apply if the target ref is checked out by any source
worktree. There is no force or acknowledgement bypass. The human must switch
or detach that worktree and retry with a new observed project version and
expected-old value.

Before writing apply intent, the trusted host creates an immutable, bounded,
full-closure pack and manifest. Repository-data limits are independent of
turn-artifact limits. Default v1 limits are:

```text
max_pack_bytes = 32 GiB
max_objects = 10,000,000
max_host_git_elapsed = 30 min
```

Exceeding a limit returns `repository_too_large` before any source write. The
manifest fixes the project/version/base/checkpoint, source repository
identity, object format/count, pack SHA-256 and Git checksum, exact Git
path/version/contract hash, and accepted daemon epoch.

If a bounded host Git operation times out, recovery identifies and removes
only the exact operation-owned temporary pack/index paths after revalidating
their parent, ownership, type, and operation identity. It never prunes or
cleans the source object database and never uses an unresolved glob. An
already-published immutable pack/manifest remains governed by the journal and
is not timeout debris.

The durable apply journal has these states:

```text
intent -> objects_imported -> ref_updated -> applied
                         \-> conflict
```

The sequence is:

1. Strictly verify, fsync, and publish the pack and manifest at an immutable
   deterministic path, then durably write `intent`.
2. Use exact `git index-pack --strict` semantics to add only content-addressed
   pack/index objects to the source object directory.
3. Revalidate that the source resolves the exact checkpoint, the graph is
   complete and fast-forward, and the target still equals expected-old; then
   compare-and-swap the journal to `objects_imported`.
4. Run `git update-ref <target> <new> <expected-old>` with all configuration,
   hook, and identity constraints above.
5. Observe the ref, write `ref_updated`, and finally compare-and-swap the
   project and apply operation to `applied`.

The apply path must not write source config, index, worktree, `FETCH_HEAD`,
another ref, or a temporary ref, and must not invoke gc, repack, prune,
maintenance, fetch, checkout, merge, rebase, reset, or push.

The verified pack and manifest remain available from before `intent` until
`applied`. Recovery from `objects_imported` must revalidate object reachability
and idempotently re-import the retained pack if concurrent prune removed
unreachable objects. After an update-ref/journal crash, an observed new value
advances, an observed old value can retry, and any other value conflicts.

## Empty-root durable sandbox

Codex developers, Codex and Claude reviewers, and Codex architects move to one
new versioned empty-root bubblewrap contract. It does not read-only bind host
`/`.

Read-only inputs are limited to:

- `/usr` and `/etc`;
- `/run/systemd/resolve` only when needed as the resolver symlink target;
- exact approved native executables;
- exact versioned toolchain lease roots;
- the exact native auth source mounted at an isolated native target;
- the reviewer snapshot, for a reviewer only.

Private/generated mounts are:

- a private PID namespace and `/proc`;
- private `/dev` and per-sandbox `/dev/shm`;
- tmpfs `/tmp`, `/var/tmp`, and `/hcom/run`;
- normalized `/hcom/home`, `/hcom/native`, `/hcom/workspace`,
  `/hcom/artifacts`, and `/hcom/toolchains/<id>`.

Writable mounts are limited to isolated HOME/native configuration,
isolated temp/runtime, the exact current-attempt artifact directory, and the
developer workspace for a developer only. `/bin`, `/sbin`, `/lib`, and
`/lib64` are fixed symlinks into read-only `/usr`.

The manifest must not mount host `/`, `/home`, Store v1, the source repository,
another project/worktree/snapshot, host temp/runtime, another relay, or an
unapproved tool root. Native argv, environment, working directory, and private
`/proc` must not reveal host source or other-role paths. Host-side process
identity checks use executable identity and `/proc/<pid>/exe`
device/inode/mode/UID plus process birth; they do not require a
namespace-internal path to canonicalize on the host.

`/etc` remains host-wide read-only system configuration. This contract claims
that user home, source, Store, worktree, runtime, temp, and unapproved tool
roots are hidden; it does not claim that no host-wide data is readable.

## Toolchain and parent-environment lease

The durable lane does not inherit `PATH` wholesale. An in-memory
`ExecutionEnvironmentLease` provides bounded, versioned toolchain roots. The
local hcom acceptance profile may map read-only Rust `.cargo/bin` and
`.rustup` roots to normalized toolchain paths. `CARGO_HOME` is isolated and
writable; `RUSTUP_HOME` is leased read-only. Host Cargo credentials, global
Cargo configuration/cache, SSH/GPG/browser/keyring data are not mounted.
Network Cargo fetches into isolated `CARGO_HOME` are permitted by this profile,
so it is not described as offline or hermetic.

Every architect, developer, and reviewer native process must inherit the exact
present values of these variables from the human parent environment that
starts or resumes the durable run:

```text
https_proxy
http_proxy
all_proxy
no_proxy
HTTPS_PROXY
HTTP_PROXY
ALL_PROXY
NO_PROXY
```

This is a hard invariant:

- uppercase and lowercase names remain independent and byte-for-byte exact;
- an unset parent variable remains unset;
- no value is normalized, synthesized, merged, or allowed to override its
  differently cased peer;
- values receive only bounded-length, NUL, and control-character shape checks;
- raw values are never parsed, printed, persisted, included in argv, Store v1,
  artifacts, status/log output, hash-input dumps, or review evidence;
- because a proxy may contain credentials, its raw value exists only in the
  private human-client-to-daemon in-memory lease and the exact child
  environment;
- a foreground architect inherits from its current human parent;
- a background worker receives the values supplied by the human client at
  `project run/resume` or architect launch and never inherits an accidental
  systemd user-manager or long-lived daemon proxy environment;
- a daemon epoch change invalidates the lease. No architect/worker child may
  spawn or resume until a human client renews the closed allowlist.

This amendment deliberately narrows the Phase 3 case-ambiguity guard. Linux
child environments treat names case-sensitively, so exactly these four pairs
may coexist as independent captured/inherited entries:

```text
(http_proxy, HTTP_PROXY)
(https_proxy, HTTPS_PROXY)
(all_proxy, ALL_PROXY)
(no_proxy, NO_PROXY)
```

The Phase 8 implementation must change the case-fold collision check in
`ExecutionEnvironmentLease::capture` and the inherited-name check performed by
`EnvironmentLeaseDescriptor::validate` so that only those exact pairs are
allowed. Exact duplicate names remain forbidden. Mixed spellings such as
`Http_Proxy`, and every other case-fold collision, remain forbidden. The
case-uniqueness guard for `required_names` remains unchanged. The foreground
architect capture/materialization path must enforce the same exact-pair rule;
it must not gain a general case-insensitive exception.

Other environment variables remain closed-allowlist inputs. The durable lane
does not guess missing values from configuration, historical processes, or the
daemon's launch environment.

## Required falsification evidence

The exact amended profile must prove, rather than infer:

- real Codex and Claude create plus exact native-session resume with the
  required model/reasoning/policy and structured terminal result;
- developer write/test/commit and reviewer/architect read-only behavior;
- exact inheritance of each present lowercase and uppercase proxy variable,
  preservation of unset values, and absence from argv, persistence, artifacts,
  logs, and evidence;
- a red test that captures at least one lowercase/uppercase proxy pair with
  distinct safe values, materializes and spawns a safe probe child, and proves
  both names and byte-for-byte values reach that child without either
  overriding the other; companion red tests must continue to reject an exact
  duplicate, a mixed-case proxy spelling, and a non-proxy case-fold collision;
- workspace/artifact/auth visibility by role and `ENOENT` for source, Store,
  sibling workspaces, other snapshots, control/registration/relay paths, and
  host temp sentinels;
- private `/proc`, `/dev/shm`, normalized native paths, and no host path in
  child argv/environment/working directory;
- standalone object stores without hardlinks or alternates;
- source inability to resolve the new commit before import, ability to resolve
  it after import while the target ref remains old, and exact expected-old
  update only after verification;
- rejection before ref mutation for corrupt, incomplete, thin, mismatched, or
  oversized transfer data;
- crash recovery at every journal boundary, idempotent re-import, checked-out
  target refusal, target drift conflict, and no hook sentinel execution;
- byte/identity stability for source hooks, config, index, worktree,
  `FETCH_HEAD`, non-target refs, retained v24 state, installed binaries, and
  existing terminals.

Until the documentation review and real capability re-probe both pass, Phase 8
production implementation remains blocked.
